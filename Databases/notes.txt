2: SQL vs NoSQL
SQL is synonymous with Dbs, Structured Query Language
Sql dbs are relational which means that data stored is interconnected.
There is a strict structure to the data which is organized into tables.

NoSQL dbs are non relational, this means that the data is defined with a looser structure and less strict relationships.
These can be more flexible and allow for less rigid data structure.

Sql is short for Structured Query Language and it is used to store, access and manipulate data within a db.
We write commands, or queries to perform actions on tables within a db. Very popular Language

db tables and relationships are defined by a schema, which is a representation of the columns and types in the table.
Connections are shown between the different db tables.
A table has unique indentifiers and properties like text numbers. Also an entitiy diagram shows relationships from different tables

NoSQL dbs are less structured than SQL dbs. They are more flexible which allows for looser data shapes.
An example is an object in JS or Python. Various types of NoSQL dbs can be used for different types of apps.

One example is MongoDB, which stores document stores, these store data in documents, like JSON where each document represents a record.
Documents can vary in structure, each having different sets of fields. One way of using a db like this is in a CMS (content management system)

Other type of NoSQL db is Redis, which stores data as a collection of key-value pairs which can be anything from a simple string to more complex data structures like arrays or objects.
API's will often use this type of database as they dont rely on relational data.

Other example = Cassandra is a Column Family Stores, which are designed for handling large volumes of data across distributed systems.
Data is stored as columns rather than rows, grouped into column families, and these can be used for time-series dara, logging and event tracking.

A last example, neo4j are dbs that are optimized for representing and querying relationships.
Data is stored in nodes (entities) and edges (relationships) with properties on both.
This system is useful for social networking apps

Differences recapped:

sql | NoSQL

data structure - fixed schema tables | flexible
schema - rigid | schema less or dynamic
scalability - vertical scaleup | horizontal scaleout
query language - sql | varied
use cases - structured data, complex joins | large scale, unstructured or semi-structured data

3: developing with dbs
Apps usually have 3 parts:
1. Frontend - A web browser
2. Backend - Server and an API
3.  Database - our RBDMS such as Postgres DB

There are Various libraries that help for using dbs in our apps, like SQLite or SQLAlchemy.
We will be using simple Node.js with PGLite DB in practice excercises

Other ways to interact with dbs in apps is ORMs, Object Relational Mapping is a method of interacting with databases which allows use of an object oriented approach, rather than directly using SQL queries.
This means that we can write queries in languages like JS or Python as part of an app.
This can have the advantage of developers avoiding to learn complex SQL. This is useful for dev teams where the dbs have limited complexity.
If an app has complex apps and devs need full control over a db, RBDMS is preferible

One example of an ORM is Prisma, whose queries look more like calling methods and use objects to define what info to retrieve
Prisma Query example :
    const user = await prisma.user.findFirst({
        select: (
            email: true,
            name: true,
        ),
    })

4: Managed vs self hosted

Db administration - this is the practice of managing a production db with regards to creating or dropping tables, managing access, and otherwise controlling data.

Managed DB - a managed database is a cloud based solution provided by a 3rd-party provider. This avoids the complexity of managing infrastructure
Managed DB have benefits like flexibility to scale as the db requirements increase, optimizing costs by scaling resources with the size of the DB, and removing the burden of mantaining db security and integrity.

Self hosted DBs are run on infrastructure owned in house by an organization. Usually these will run on a physical server but also a VM or Docker machine
benefits incluce greater custimizabiility in configuration, add custom layers of security for sensitive use cases and industries, and no reliance on 3rd party management

In recap, managed dbs have quick startup and lower overheads, but can be costly and always rely on external management. Self hosted DBs, offer higher flexibility customization and security with lower costs. But an app which is small it can be overkill and expensive to set up and mantaining it.
